VZ: MusicBrainz — Show All Entity Data In A Consolidated View
=============================================================

PURPOSE
-------
Consolidates paginated and non-paginated MusicBrainz table lists (Events,
Recordings, Releases, Works, Artists, Labels, Release Groups, Tags, and more)
into a single scrollable, filterable, sortable view.

SUPPORTED PAGES
---------------
• Artist:   Release Groups, Releases, Recordings, Works, Events, Aliases,
            Relationships (including filtered link_type_id pages)
• Release Group, Release, Recording, Work, Label, Series, Place, Area,
  Instrument, Event pages — all supported sub-tabs
• Collection pages (own collections, subscribed collections, entity sub-tabs
  including Release groups with native h3-grouped sub-tables)
• Account pages (/account/applications — authorized and developer
  applications) — see ACCOUNT APPLICATIONS PAGE below
• Tag pages — entity tag pages (/tag/<value>, /tag/<value>/<entity>),
  user tag pages (/user/*/tags, /user/*/tag/*),
  and the MusicBrainz Most Popular Tags page (/tags)
• Search result pages (all entity types)
• Report pages — the /reports index (all 117 reports across 14 categories)
  and individual /report/<ReportName> pages (with buttons to switch between
  all results and results limited to your subscribed entities)
• Edit-listing pages — /search/edits, /<entity>/<mbid>/edits,
  /edit/subscribed, /edit/subscribed_editors, /user/<username>/edits,
  /user/<username>/edits/open, and /edit/notes-received ("Recent notes left
  on your edits") — see EDIT-LISTING PAGES below
• Auto-editor elections (/elections) and individual election pages
  (/election/<n>)
• Genre list (/genres), Instrument list (/instruments), Edit Types
  documentation (/doc/Edit_Types), Top CD stubs (/cdstub/browse), and
  individual CD stub pages (/cdstub/<disc-id>)
• Privileged user accounts (/privileged)
• Also works on the musicbrainz.eu mirror domain, in addition to
  musicbrainz.org

GETTING STARTED
---------------
1. Navigate to any supported MusicBrainz entity page (e.g. an Artist's
   Recordings tab).
2. Click the action button (labelled "Show all …", "🧮¹ Show all …", or a
   page-specific label) in the controls bar to start fetching all pages from
   the MusicBrainz database.  Action buttons carry a 🧮N superscript prefix
   where N is the Ctrl-M prefix mnemonic index (1–9) for keyboard access.
3. A real-time progress bar (light-red → orange → light-green) tracks the
   fetch.  Click "Stop" at any time to abort; or press the prefix key then "o"
   while the Stop button is visible.
4. When complete, the consolidated table appears with filtering, sorting, and
   all UI features active.  The global filter is auto-focused so you can start
   typing immediately.

ACTION BUTTONS
--------------
• 💾 Save to Disk    — save the current dataset as a compressed .json.gz file
                       (~60–80% smaller than plain JSON); the filename encodes
                       page type, context detail, row count, and timestamp
• 📂 Load from Disk  — load a previously saved dataset via the three-phase
                       Load → Filter → Render dialog (see PRE-FILTER section)
• ↔️ Resize          — fit all columns to their content (toggle to restore)
• 📊 Statistics       — show a statistics panel (row/column counts, artwork, …)
• 📏 Density         — choose Compact / Normal / Comfortable row spacing
• 👁️ Visible         — show/hide individual table columns; Alt-S / Alt-D to
                       select/deselect all; navigate with ↑/↓ / Tab / Shift-Tab
• 💾 Export          — export visible data as CSV, JSON, or Emacs Org-Mode
• 🎹                 — show keyboard shortcuts reference (or press ? / /)
• ⚙️                  — open the Settings Manager to configure all options
• ❓                 — show this help dialog

FILTERING
---------
• Global Filter — large input box at the top filters all columns at once
• Column Filters — per-column filter row below the table header
• Sub-table Filters — independent filter inputs above each sub-table on
  multi-table pages (e.g. Artist-Relationships)
• All filter inputs support plain text, case-sensitive (Cc checkbox),
  regexp (Rx checkbox), and exclude-matches (Ex checkbox) mode — tick Ex to
  hide rows that match instead of keeping them
• Filter highlighting works across inline HTML element boundaries (cross-tag
  matching) — search terms spanning <a>, <bdi>, or <span> elements highlight
  correctly in all three filter levels
• Ctrl-G  — focus global filter field (configurable; requires "Enable Direct
            Ctrl+Letter Shortcuts" — off by default; use prefix+G otherwise
            — see KEYBOARD SHORTCUTS below)
• Ctrl-C  — focus first column filter; repeated presses cycle through tables
            (configurable; same direct-shortcuts requirement as Ctrl-G above)
• Ctrl-U  — open Unicode character picker (when any text input is focused;
            configurable; never suppressed) — insert special characters
            into filter strings
• Ctrl-Shift-G — clear all active filters (configurable; never suppressed;
                also activates the "✕ Clear ALL filters" button)
• Shift-Esc    — clear all COLUMN filters only (global — works from anywhere)
• Escape  — first press clears the focused filter, second press removes focus
• 🎨 Toggle highlighting — toggle highlight colours on/off for active filters

FILTER STATUS DISPLAY
---------------------
A filter status span below each sub-table header (and next to the global filter
bar on single-table pages) shows a real-time summary of active filters and the
resulting row count:

  ✓ Filtered 55 rows [GLOBAL:"bruce", SUB-TABLE:"vinyl"]
  ✓ Filtered 19 rows [GLOBAL:"bruce", SUB-TABLE:"vinyl", 1 COLUMN FILTER ['Release':"version"]]
  ✓ Sorted by: "Year"▲ (133 rows)

• Global, sub-table, and column filters are shown together in one compact line.
• Column filter details are expanded when exactly one column filter is active;
  when multiple are active they are shown as a count only.
• The status clears automatically when all filters are removed.

HIDDEN-MATCH INDICATOR ON MULTI-ROW COLLAPSE BUTTONS
-----------------------------------------------------
When a filter is active and its highlighted match is hidden inside a collapsed
multi-row cell (Catalog#, Label, …) the ▶ expand button for that cell turns
yellow with a red glyph, signalling that relevant content is hidden.  The same
tinting is applied to the sub-table-level "Expand all multi-row cells" button
when any collapsed cell in the sub-table contains a hidden match.  Clicking the
button expands the cells and reveals the highlighted content.


-------------------------------------
Every filter input transitions through three visual states:
• Idle (empty)  — configurable border color (global default: black,
                  sub-table default: #cccccc)
• Active (has text) — configurable border color (global default: orange,
                      sub-table default: green)
• Error (invalid RegExp when Rx is on) — shared configurable error color
  (default: dark red #cc0000, border width increases to 4 px for visibility);
  an "⚠ Invalid regexp: …" message is written to the filter status area
Both global and sub-table filter fields are resizable via a ⋮ drag handle
to their right; initial widths are configurable in ⚙️ Settings.

COLUMN FILTER FOCUS INDICATORS
--------------------------------
When a column filter field is focused (via Ctrl-C, Tab, or mouse click):
• A configurable search-icon prefix (default "🔍 ") is prepended to the field
  to make it immediately obvious which column is being edited.  The prefix is
  purely decorative: it is never included in the actual filter string.
• The field background turns light yellow (configurable colour
  "Column Filter Focus Background", default #fffde7).
• The prefix cannot be deleted or selected — Backspace, Delete, ArrowLeft,
  and Home are clamped so the cursor stays at or after the prefix.  Ctrl+A
  selects only the user-editable text after the prefix.
When the field loses focus:
• The prefix is always removed from the stored value.
• If the user entered a filter string the background switches to a persistent
  "active" colour (configurable "Column Filter Active Background", default
  #fff9c4), providing a visual overview of which columns have active filters.
• If the field was cleared the background is removed entirely.
Both colours and the prefix string are configurable in ⚙️ Settings →
🎨 TABLE FILTER CONFIGURATION.

FILTER HISTORY & PINNED FILTER LIST
-------------------------------------
Every filter expression entered in the global filter or the Load-from-Disk
pre-filter is saved to an LRU history (configurable limit, default 50 entries).
A ▼ dropdown toggle opens the history panel, which shows two sections:

• 📌 Pinned — a persistent list of expressions that never age out.  Entries
  can be added (★ pin button next to any LRU item), edited, and removed via
  the "✎ Edit Pinned Filter List" button (Alt+E in the panel, or via ⚙️
  Settings → 💾 LOAD AND SAVE DATA TO/FROM DISK → "Edit Pinned Filter List").

• LRU History — the most recent N expressions (most recent first).  Clicking
  any entry applies it immediately; the ★ button pins it permanently.

UNICODE CHARACTER PICKER  (Ctrl+U when a text input is focused)
----------------------------------------------------------------
When any text input or textarea is focused, Ctrl+U (configurable) opens a
small popup listing all configured Unicode glyphs.  Clicking a glyph inserts
it at the cursor position in the focused field.  The mapping table (character
→ name → examples) is fully configurable in ⚙️ Settings →
🔤 UNICODE CHARACTER PICKER.

UNIQUE-VALUES COLUMN DROPDOWN  (📊 button in every column header)
------------------------------------------------------------------
Each column header contains a 📊 button that opens a scrollable panel listing
every distinct non-empty value currently visible in that column.

• Occurrence count badge — each entry is prefixed by a styled "(n)" badge
  showing how many visible rows contain that value.  All badges within one
  column share a uniform monospace width so the numbers right-align:
      (12) value A
    (5678) value B
   (21345) value C
  Badge text and background colors are configurable in ⚙️ Settings →
  🎨 TABLE FILTER CONFIGURATION ("Unique-Values Count Badge" settings).
• Quick-filter bar — a "Quick filter…" input at the top of the panel is
  auto-focused when the panel opens.  Type to narrow the item list in real
  time; matching substrings are highlighted (configurable colors).  A ×
  button clears the filter.
• Multi-select checkboxes — each value shows a ☑/☐ checkbox. Clicking a
  value (or pressing Enter on a keyboard-focused value) toggles its
  checkbox and keeps the panel open instead of replacing the filter and
  closing; every checked value is OR'd together into a single column
  filter. Typing plain text or picking a "Cell structure" entry is mutually
  exclusive with checkbox selection — whichever you use last wins and
  clears the other.
• Navigate with ↑/↓ / Home / End; Enter toggles the keyboard-focused value's
  checkbox the same way clicking it does.
• Escape — first press clears the quickfilter (if non-empty); second press
  (or first press when quickfilter is already empty) closes the panel.
• The panel closes automatically when clicking outside it or when the page
  is scrolled (scrolling inside the panel itself does not close it).
• Cache-status emoji (🟢/🟡/🔵/🗄️/⚠️) injected into CAA/EAA artwork columns
  are automatically excluded so that release/event title text is never mixed
  with artwork metadata in the dropdown values.
• Flag icons (optional, off by default) — enable "Show Flag Icons In
  Unique-Values Dropdown" in ⚙️ Settings to decorate each entry with the same
  flag icon shown in the table cell, for Country/Area/Locality/Region/
  Location/Place/Country-Date columns (including subdivision icons added by
  separately-installed userscripts such as "More Flags Everywhere").

PRE-FILTER (Load from Disk — three-phase dialog)
-------------------------------------------------
The Load-from-Disk dialog works as a sequential three-phase workflow:

  Phase 1 — Load:   Click "Load Data" (Alt+L) to pick a .json.gz or .json
                    file.  The entire file is read and parsed into memory.
                    A ✅ status line reports the row count and filename.

  Phase 2 — Filter: Enter an optional filter expression (plain text, RegExp,
                    or Exclude Matches) using the Cc / Rx / Ex toggles, then
                    click "Filter Data" (Alt+F).  Matching rows are counted
                    in memory — no DOM changes occur yet.  The count is shown
                    ("N of T rows match → will be rendered").

  Phase 3 — Render: Click "Render Data" (Alt+R) to apply the filter and
                    render the matched rows.  The dialog closes when done.

• The last N expressions (configurable via "Load Filter History Limit") are
  saved and accessible via the ▼ dropdown toggle next to the filter field.
• Pre-filtered rows are highlighted with 🎨; toggle highlighting with the
  dynamic prefilter button that appears in the filter bar.
• Escape dismisses the dialog at any phase.

SORTING
-------
• Click any column header (⇅) to sort ascending; click again for descending;
  click the ⇅ icon again to restore original order
• Visual indicator changes to ▲ / ▼ on the active sort column
• Multi-column sort: Ctrl+Click ▲ or ▼ to add a column to the sort chain;
  superscript numbers (¹²³…) show each column's priority; plain click returns
  to single-column mode
• Large tables use an async chunked merge-sort; a progress indicator is shown
  when the row count exceeds the configurable sort-progress threshold

COLLAPSING / EXPANDING
-----------------------
• Click an h2 header to collapse/expand its table section
• Ctrl-Click an h2 to toggle all h2 headers simultaneously (or use Ctrl-2)
• Click an h3 header to collapse/expand its type group
• Ctrl-Click an h3 to toggle all h3 headers simultaneously (or use Ctrl-3)
• Show All / Hide All links available per section

SAVE & LOAD (Offline Cache)
----------------------------
• Datasets are saved as gzip-compressed JSON (.json.gz) — ~60–80% smaller
  than plain JSON.
• Generated filenames follow: MB-<pageType>[-<detail>-]<rowCount>-<timestamp>.json.gz
  The optional <detail> slug is derived from the active button label (on
  multi-button pages) or from the relationship h2 heading (on link_type_id
  filtered pages), making saved files immediately distinguishable.
• When loading, enter an optional pre-filter expression (plain text, RegExp,
  or Exclude-Matches mode) to import only the rows you need.
• Load filter history (last N expressions, configurable) is accessible via the
  ▼ dropdown in the Load dialog.
• Pre-filtered rows are highlighted with 🎨; toggle highlighting with the
  dynamic prefilter button.

COLUMN MANAGEMENT
-----------------
• 👁️ Visible menu — check/uncheck any column; Select All (Alt-S) /
  Deselect All (Alt-D); button turns red when any column is hidden
• Manual resize — drag column-header edges with the mouse at any time
• Resize — calculates optimal widths for content including images/icons;
  acts as a toggle (restores original widths on second click)
• Column origin — each column header is classified into one of three tiers,
  each with a distinct background color (configurable in ⚙️ Settings →
  🖌️ ELEMENT UI STYLES):
    — Original columns  (no special tint) — present on the original page
    — Extracted columns (greenish grey, default #b8c8b8) — split or injected
                        from original columns via columnExtractors
    — Derived columns   (warm beige, default #c8c8b0) — further split from
                        extracted columns via syntheticColumnExtractors
  The Statistics panel Table Details section tints each column row with the
  same color for a quick visual origin overview.
• Extracted columns added by the script alongside the raw data:
    — "Country" + "Date"        split from the combined "Country/Date" cell on
                                release and label pages
    — "Place" + "Locality" + "Region" + "Country"  split from the "Location"
                                cell on event and area pages (and from the
                                "Place" cell, as "MB-Place", on Place-category
                                report pages, e.g. AnnotationsPlaces)
    — "MB-Area" + "MB-Locality" + "MB-Region" + "Country"  split from the
                                "Area" cell on label, area, and recording pages
    — "MB-Begin area" + "MB-Begin locality" + "MB-Begin region" +
      "Begin country"          split from the "Begin area" cell on
                                area-artists and similar pages
    — "MB-End area" + "MB-End locality" + "MB-End region" + "End country"
                                split from the "End area" cell on
                                area-artists and similar pages
      (Locality is the first/most-specific area link, e.g. a city; Region is
      every subsequent one, comma-joined — a positional split, since
      MusicBrainz area links carry no type information. A bare subdivision
      flag icon added by a separately-installed userscript, with no city
      ever entered, is routed to Region instead of Locality for United
      States/United Kingdom/Canada/Australia.)
    — "Total Tracks"            computed from track-count data on release pages
    — "Format Types"            strips quantity prefixes (e.g. "8×") from
                                the Format column on release-group, label, and
                                series pages
    — "CAA" / "EAA"             cover / event art thumbnail column on pages
                                that carry artwork
    — "Video"                   extracted from the Title cell on recording pages
    — "Cancelled"               extracted from the Event cell on event pages
    — "Primary Alias"           extracted from the main entity name cell on
                                applicable pages
    — "MB-Name" + "Comment"     extracted from the main entity name cell on
                                pages that expose the raw MusicBrainz entity
                                name alongside its disambiguation comment
    — "Last edited date" + "Last edited time"  split from report pages'
                                native "Last edited" timestamp column
    — "Annotation chars"        character count of the "Annotation" column,
                                on report pages, for sorting/filtering by size
• Derived columns (split from already-extracted columns):
    — "DD" + "MM" + "YYYY" + "Day" + "Month"  derived from the extracted "Date"
                                column on release, label, event, and work pages
    — "B-DD" + "B-MM" + "B-YYYY" + "B-Day" + "B-Month"  derived from "Begin"
                                date on artist, area-artist, and label pages
    — "E-DD" + "E-MM" + "E-YYYY" + "E-Day" + "E-Month"  derived from "End"
                                date on artist, area-artist, and label pages
    — "Event-Type" + "Event-Date" + "Event-Detail" + "Event-Venue" +
      "Event-Venue-Detail" + "Event-City" + "Event-State" + "Event-Country"
                                derived from the extracted "Comment" column on
                                Work-Recordings pages (requires "Enable Event
                                Parts synthetic column extractor" setting)

NUMERIC COLUMN ALIGNMENT  (🔢 NUMERIC COLUMN ALIGNMENT in ⚙️ Settings)
------------------------------------------------------------------------
Date-part columns (DD, MM, YYYY and their B-/E- prefixed variants) and other
declared integer columns are right- or center-aligned with uniform
inline-block wrapping so values line up vertically regardless of digit count.
The "Length" column on recording pages uses colon-split alignment so the ":"
separator lines up across all rows.  Numeric alignment can be disabled
globally in ⚙️ Settings.

ANNOTATION COLUMNS  (📝 ANNOTATION COLUMNS in ⚙️ Settings)
------------------------------------------------------------
Free-text columns declared as collapsable (e.g. "Annotation" on report pages
such as AnnotationsPlaces/AnnotationsReleases, and the instrument
Annotations report) are height-clamped behind a ▶/▼ "show more/less" toggle,
the same way multi-row list columns (Catalog#, Label, …) collapse — only
cells that actually overflow the clamp get a toggle.
• Enable/disable the collapse behaviour, and configure the clamp height (em)
  and the auto-resize max width (px) applied to these columns — the width
  cap stays active even when collapsing is disabled.
• Wiki-rendered <h2> sub-headings inside an Annotation cell (e.g.
  "== Known performances ==") get their own configurable background/text
  color, separate from the page-level H2 section-header colors.
• Ctrl+Click a cell's ▶/▼ toggle (or the column header's toggle) to expand
  the cell/column AND every nested wiki <h2> sub-heading inside it in one
  step; the tooltip mentions this only when the cell actually has one.

ANNOTATION SECTION AUTO-EXPAND  (📖 ANNOTATION SECTION (Entity Pages) in ⚙️ Settings)
----------------------------------------------------------------------------------------
On entity pages (e.g. /work/<mbid>) with a native "Annotation" section, this
optional setting (off by default) clicks the native "Show more…" link on
load so a long annotation is fully visible immediately instead of truncated.
Unrelated to the ANNOTATION COLUMNS feature above, which only affects this
script's own rendered table columns.

CAA/EAA ILLUSTRATED DISCOGRAPHY  (🖼️ in ⚙️ Settings)
------------------------------------------------------
• Enable CAA/EAA Illustrated Discography — loads cover/event art thumbnails
  after rendering.  Three display modes, all independently togglable:
    — Small icon column — tiny thumbnail in the CAA/EAA column header cell
    — Big picture strip — a horizontal scrollable strip of large images
                          above each sub-table that has artwork
    — Inline thumbnails — a 20×20 px thumbnail inside each Release/Title
                          column cell next to the release-group/release name
• Big picture strip — a 🖼️ toggle button in each h3/h2 header shows/hides
  the strip per sub-table; a global toggle in the h2 header controls all
  strips at once.  Retry buttons (⟳ and 🔗⟳) force a fresh network fetch
  with IDB cache invalidation.
• Inline thumbnails — display context-aware tooltips (driven by tooltipColumns
  in the page definition) when hovering; tooltip shows name, comment, artist,
  format, etc. depending on the page type.
• Cache-hint indicators (🟢 memory / 🟡 network / 🔵 IDB / 🗄️ timed /
  ⚠️ unknown) can be shown as overlays on big-strip images, inline thumbnails,
  and the count badge in the icon column.  Configurable in ⚙️ Settings →
  ⏱️ RESOURCE TIMING API.

EXPAND RELEASE GROUPS  (🔍 in ⚙️ Settings)
--------------------------------------------
On Artist, Label, Release-Group, Series, Recording, and Collection pages,
each release-group link cell receives an inline ▶/▼ toggle button.  Clicking
it expands an inline sub-table showing all releases for that release group
(title, format, track count, date, country, status).  Each release row also
gets its own ▶/▼ button for expanding a track listing.  Clicking again
collapses the sub-table.

RELEASE EVENTS COLUMN  (📅 in ⚙️ Settings)
--------------------------------------------
On pages that declare injectedColumns:["Release events"] the script injects
an extra "Release events" column and populates it asynchronously from the
MusicBrainz Web Service (one WS2 call per release row).  The column shows
release event dates and countries after the table renders.

RELATIONSHIPS COLUMN  (🔗 in ⚙️ Settings)
--------------------------------------------
On pages that declare injectedColumns:["Relationships"] the script injects
a "Relationships" column populated asynchronously from the MusicBrainz
Web Service.  Relationship icons (favicons) appear after the table renders.

• Rich filter-aware tooltip — when a filter is active and it matches content
  in a Relationships cell, hovering an icon in that cell opens a rich HTML
  tooltip showing the full URL.  The tooltip is suppressed when no active
  filter matches that specific cell, to avoid intrusive popups during normal
  browsing.
• Filter match highlighting — when a filter expression matches a URL in the
  Relationships cell, the corresponding relationship icon is highlighted with
  a coloured border/background so the match is immediately visible.
• Relationship data is cached in IndexedDB (7-day TTL) to avoid re-fetching
  on repeated visits.  Retry buttons (⟳) force a fresh network fetch with
  IDB cache invalidation.

EDIT-LISTING PAGES  (🎨 EDITS PAGE in ⚙️ Settings)
----------------------------------------------------
Covers /search/edits, /<entity>/<mbid>/edits, /edit/subscribed,
/edit/subscribed_editors, /user/<username>/edits(/open), and
/edit/notes-received. Each native edit block is converted into a table row
(Edit#, Edit action, Edit details, Edit notes, Entered from release, By
artist, Edit by, My vote, Vote count, Closed/Approved, Voting, Edit status —
notes-received instead shows Edit#, Edit action, User, Date/Time, Vote,
Edit notes).
• "Edit details" and "Edit notes" are collapsable/height-clamped the same
  way Annotation columns are, with independent settings controlling whether
  they start expanded (default) or collapsed.
• "Edit#"/"Edit action" are colored by edit category and open/closed state
  (matching the well-known "MusicBrainz: Colourful edits" userscript's
  palette), independently of whether that script is installed. Old/new
  value diff cells inside "Edit details" compare tables, and zebra striping
  on nested compare tables (e.g. a medium edit's tracklist grid), are also
  colored to match MusicBrainz's own site styling. All colors and the
  master toggle are configurable in ⚙️ Settings → 🎨 EDITS PAGE.
• Inline CAA cover-art thumbnails for release/release-group links found in
  "Entered from release".
• Pages with an ambiguous "Found at least N edits" pagination widget
  (uncounted, growing result sets) use a safety-capped fetch-until-empty
  strategy instead of trusting the widget's page-number links.

ACCOUNT APPLICATIONS PAGE  (/account/applications)
-----------------------------------------------------
Shows your "Authorized applications" (OAuth2 apps you've granted access) and
"Developer applications" (apps you've registered) as two consolidated
tables, via a single "Show all Applications" button — a static page, no
pagination.
• Unlike other MusicBrainz pages, /account/* is served with a stricter
  Content-Security-Policy (style-src 'self' staticbrainz.org
  static.metabrainz.org, no unsafe-inline) that blocks plain inline <style>
  elements and style="..." attributes outright. Every dialog, tooltip, and
  panel in this script is built with GM_addStyle()-injected stylesheets
  instead, so all features render correctly here exactly as they do
  elsewhere — no reduced functionality on this page.

H1 ALIAS LINE
-------------
On Release Group and Event pages MusicBrainz sometimes places the primary alias
inside the h1 title.  The script relocates that alias into a dedicated italic
line immediately below the title: «Primary alias: …», keeping the title line
and action buttons uncluttered.  Extra show-title text (when present alongside
the alias in the same span) is preserved as a new comment span in the h1.
Additional relocations (configurable):
• Legal name paragraph — moved below the subheader on artist-releasegroups pages
• Trailing h2 sections (e.g. "Relationships", "Related works") — moved before
  the data table h2 for easier navigation

  Normal      — default MusicBrainz-like spacing
  Comfortable — larger padding for easier reading
  Navigate with ↑/↓ in the menu for an immediate live preview; Enter to apply

PROGRESS BAR
------------

• A time estimate ("est. X.Xs left") is shown inside the bar.

STATISTICS PANEL (📊 or Ctrl+I)
--------------------------------
The Statistics panel is a draggable, resizable overlay showing two sections:

§ Global Statistics
  A table of page-wide metrics (alphabetically by icon):
  • 🌎 / 🗄️ Network / IndexedDB loading time for CAA/EAA artwork
  • 💾 Estimated memory usage
  • 📄 Page type and 🗂️ Table mode (single / multi)
  • 📑 Sub-table count and 📋 Total table rows
  • 🖼️ Total table rows with CAA/EAA artwork — confirmed rows whose front art
       was found; reads from the per-table toggle button badge (incremented on
       each successful image load), NOT estimated from link count.  Shows "—"
       while artwork is still downloading and updates automatically when all
       loading completes.
  • 🔲 Total original columns — <th> cells present on the original MB page
  • 🔀 Total extracted columns — injected via columnExtractors / extractMainColumn
  • 🔁 Total derived columns   — further split via syntheticColumnExtractors
  • ⬛ Total columns — sum of original + extracted + derived
  • 👁️ Visible columns and 🙈 Hidden columns
  • 🔍 Global filter, 📂 Sub-table filters, 🔠 Column filters summary
  • ↔️ Resize status and 📐 Manually resized column count

§ Table Details  (one card per sub-table)
  Each card header row shows: entity type · active filter · row count ·
  rows with artwork.  The artwork count reads from the per-table toggle button
  badge (incremented by each confirmed image load) and shows "—" until loading
  completes; both the global total and all per-sub-table cells update
  automatically when the completion toast fires.
  Below the header a collapsible per-column breakdown lists every column with:
    — its index number
    — name (accented for extracted/derived columns)
    — visibility (✔ yes / ✘ no)
    — sort state (▲ asc / ▼ desc / ⇅ none)
    — unique-value count
    — multi-row cell count
    — active column filter expression
    — resize width (manually N px / default)
  Each row is tinted with the column's origin color (extracted = greenish grey,
  derived = warm beige, original = no tint) for quick visual reference.
  A live quick-filter at the top of the panel filters both sections in real time.

The panel is draggable and resizable; position, size, and font size are persisted
across sessions.  A "📤 Export Stats" button saves the panel content as a
self-contained HTML file.

SETTINGS DIALOG SAFETY GUARDS
------------------------------
• If you close the dialog (via the CLOSE link, Escape, or clicking outside)
  while there are unsaved changes a confirmation dialog ("Unsaved Changes")
  appears.  Click OK to discard the changes, or Cancel to return to the dialog.
• Clicking RESET always opens a confirmation dialog ("Reset All Settings to
  Defaults") before any defaults are applied. Click OK to proceed, or Cancel
  to abort.

CHANGELOG DIALOG (📜 ChangeLog in the Tampermonkey menu)
----------------------------------------------------------
• The changelog is loaded from GitHub (with a 1-hour GM cache) at startup.
• A 🔍 search field in the dialog header filters entries in real time;
  matching text is highlighted in version, date, section, and item text.
  A ✕ button clears the search field.
• A "(N filtered)" count is shown in the meta line when a search is active.
• When you open the Changelog dialog the console shows cache-status info:
  entry count, source (📦 cache / 🌐 fresh fetch / static), and cache age.
• A "🔄 Force refresh" link in the upper-right corner (left of CLOSE) bypasses
  the cache, downloads the latest changelog from GitHub, and re-renders the
  table in place — without closing the dialog.  The current search filter is
  preserved after a force refresh.
• Force-refresh success / failure is reported in the browser console and
  reflected briefly in the link label (✅ Refreshed / ⚠️ Refresh failed).

APPLICATION HELP DIALOG (❓ button or prefix key + H)
-------------------------------------------------------
• The help text is fetched from GitHub (with a 1-hour GM cache) when the
  dialog opens.  The console reports the URL, source (📦 cache / 🌐 fresh),
  and byte size.
• A "🔄 Force refresh" link in the title bar (left of ✕) downloads the latest
  help text from GitHub and re-renders the content in place.
• While a force refresh is in progress the link shows "⏳ Refreshing…", then
  briefly "✅ Refreshed" on success before returning to its default label.

LIBRARY SETTINGS (🔧 Library Settings in the Tampermonkey menu)
----------------------------------------------------------------
• A small settings editor for the shared VZ_MBLibrary, accessible from the

SIDEBAR
-------
• The page sidebar can be optionally collapsed (experimental setting) to give
  more horizontal space to the data table.
• Sticky table headers remain visible while scrolling through large tables
  (can be disabled in Settings).

MULTI-TABLE PAGES
-----------------
• On pages like Artist-Relationships or Release-Group releases the data is
  split into independent sub-tables per category, each with its own filter
  (including resizable input, idle/active/error border states, and regexp
  error reporting to the status span), sort chain, clear button, and optional
  "Show all N" overflow expander.
• A single sub-table is auto-expanded on load.
• Ctrl+Click sort applies independently per sub-table.
• Overflow sub-tables exceeding 100 rows can optionally be opened in a new
  browser tab (configurable in ⚙️ Settings → 🛠️ Generic Settings).

PAGE RELOAD NOTICE
------------------
When MusicBrainz applies a URL filter that would interfere with pagination,
the script automatically reloads the page to strip the filter.  After reload
an ⚠️ Page Reloaded notice appears and automatically re-clicks the "Show all"
button after 2 seconds (or immediately when you click OK / press Enter).
Press Escape on that notice to cancel the auto-action.
